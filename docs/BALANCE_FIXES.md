## Исправленные баги (критические)

### BUG-001: Крит не работал при ручном тапе
**Дата**: 2026-05-20  
**Файл**: `server/public/js/Game.js`, строка 187  

**Проблема**:
```js
// Было: 'Подик' не совпадает ни с одним case в getUpgradeLevel()
const criticalChance = this.upgradeManager.getUpgradeLevel('Подик') * 0.05
// → всегда возвращал 0, критический удар никогда не срабатывал
```

**Исправление**:
```js
// Стало: правильный ID апгрейда
const criticalChance = Math.min(this.upgradeManager.getUpgradeLevel('critical-hit') * 0.05, 0.80)
```

**Влияние**: Апгрейд Подик теперь реально работает при ручных кликах.

### BUG-002: XP-буст не работал при ручном тапе
**Дата**: 2026-05-20  
**Файл**: `server/public/js/Game.js`, строка 200  

**Проблема**:
```js
// Было: 'Снюс' не совпадает ни с одним case
const xpBoost = 1 + (this.upgradeManager.getUpgradeLevel('Снюс') * 0.15)
// → всегда 1.0, апгрейд Снюс не давал XP бонуса при ручных тапах
```

**Исправление**:
```js
// Стало: правильный ID
const xpBoost = 1 + (this.upgradeManager.getUpgradeLevel('xp-boost') * 0.15)
```

**Влияние**: Апгрейд Снюс теперь реально ускоряет прокачку при ручных кликах.

### BUG-003: Автокликер сбрасывался при каждом ручном тапе
**Дата**: 2026-05-20  
**Файл**: `server/public/js/Game.js`, строка 210  

**Проблема**:
```js
handleTap(event) {
  // ...
  this.upgradeManager.applyAutoClickerEffect() // вызывался при каждом тапе!
}
```
`applyAutoClickerEffect()` делает `clearInterval()` и создаёт новый — интервал постоянно сбрасывался при активном тапании.

**Исправление**: Удалён вызов `applyAutoClickerEffect()` из `handleTap`.  
Автокликер теперь запускается только при покупке и при загрузке игры.

## Баланс-изменения

### BAL-001: Кап критического шанса 80%
**Дата**: 2026-05-20  
**Файлы**: `Game.js`, `UpgradeManager.js`  

**Проблема**: Без капа Подик уровня 20 давал 100% крит-шанс, делая каждый клик критическим. Уровни 21+ были полностью бесполезны.

**Изменение**: `Math.min(criticalChance, 0.80)` в обоих местах где рассчитывается крит.

**Обоснование**: 80% — достаточно ощутимый эффект, при этом рандом остаётся в игре. Уровни Подика выше 16 всё ещё имеют смысл через дополнительный урон (если добавить scaling damage в будущем).

## Баланс-изменения Фаза 2

### BAL-002: XP scaling 1.1 → 1.08
**Дата**: 2026-05-20  
**Файл**: `server/public/js/Game.js`

**Проблема**: С множителем 1.1 к уровню 100 требовалось ~138K XP за один уровень — недостижимо без многочасового гринда.

**Изменение**: `this.xpForLevel * 1.08`

**Результат**: К уровню 100 нужно ~22K XP за уровень — в 6 раз меньше, прогрессия стала более плавной.

### BAL-003: Кап длины сообщения в чате синхронизирован
**Дата**: 2026-05-20  
**Файл**: `server/api.js`

Клиент ограничивал 32 символа, сервер резал на 200. Теперь сервер тоже принимает максимум 32 символа и возвращает 400 при превышении.

## Известные проблемы (не исправлены)

### ISSUE-001: Автокликер speed cap слишком ранний
**Уровень для достижения**: 24 (300 мс интервал)  
**Max level апгрейда**: 1500  
**Проблема**: Уровни 25-1500 дают только +15%/уровень к bonus, что стекается линейно и к уровню 1500 даёт `1 + 1500 × 0.15 = 226x` множитель — экспоненциально OP.  
**Предлагаемое решение**: Уменьшить costIncrease для высоких уровней ИЛИ изменить бонус на логарифмическую формулу после уровня 24.

### ISSUE-002: XP drought на высоких уровнях
**Проблема**: К уровню 100 нужно ~138К XP, а за один тап даётся 1 XP (min). 138К тапов ≈ 45 минут при 50 тапах/минуту — только для одного уровня.  
**Предлагаемое решение**: Снизить xpForLevel multiplier с 1.1 до 1.08, или добавить XP bonuses из других источников (ежедневный вход, ачивки).

### ISSUE-003: Алмазная засуха в середине игры
**Проблема**: После уровня 20 следующие значимые источники алмазов — уровень 50 (+8💎) и уровень 100 (+15💎). При активной игре 20→50 может занять часы без алмазов.  
**Предлагаемое решение**: Daily login reward +1💎 (см. `docs/GAME_DESIGN.md`).
